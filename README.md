# Бот записи к Динаре

Telegram-бот для записи на макияж / причёску / полный образ.
Запись → PostgreSQL → Google Calendar → уведомление мастеру в Telegram.

## Запуск

```bash
npm install
docker compose --profile postgres up -d postgres
npm run dev                                     
```

### Продакшен (Docker)

```bash
docker compose up -d --build                    
docker compose --profile postgres up -d --build 
docker compose logs -f bot                    
```

- Контейнер перезапускается сам при падении (`restart: unless-stopped`) и по healthcheck (`GET /health`).
- **Webhook**: укажите `WEBHOOK_URL` (публичный https, например за nginx/Caddy) и обязательно `WEBHOOK_SECRET` (без него бот не стартует) — бот сам зарегистрирует webhook на `<WEBHOOK_URL>/telegram`. Без `WEBHOOK_URL` работает long polling (порт наружу не нужен).
- **Алерты**: ошибки логируются и присылаются в Telegram на `ADMIN_CHAT_ID` (не чаще раза в минуту на одно место).

## Настройка

**Telegram**
1. Создать бота у @BotFather → `BOT_TOKEN`.
2. Динара пишет `/start` своему боту, затем узнаёт свой chat_id у @userinfobot → `MASTER_CHAT_ID`.

**Google Calendar**
1. Google Cloud Console → создать проект → включить *Google Calendar API*.
2. IAM → Service Accounts → создать аккаунт → Keys → Add key (JSON).
3. Из JSON: `client_email` → `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `private_key` → `GOOGLE_PRIVATE_KEY`.
4. В Google Calendar Динары: настройки календаря → «Открыть доступ» → добавить email сервисного аккаунта с правом «Внесение изменений в мероприятия».
5. Там же «Идентификатор календаря» → `GOOGLE_CALENDAR_ID` (для основного календаря — это gmail Динары).

**Как добраться** — заполнить `src/data/location.ts` (адрес, координаты, описание). Пока пусто — кнопка скрыта.

**PostgreSQL** — строка подключения в `DATABASE_URL`. Таблицы создаются автоматически при старте бота (миграции из `drizzle/`).
Схема описана в `src/db/schema.ts`; после её изменения — `npm run db:generate` (создаст новую миграцию). Посмотреть данные — `npm run db:studio`.

Без Google-кредов и `MASTER_CHAT_ID` бот тоже запустится — просто пропустит эти шаги с предупреждением в логах.

## Тексты

Все тексты лежат в `src/data/`:
- `texts.ts` — всё, что видит клиент: приветствие, кнопки, шаги записи, напоминания, отзывы, названия месяцев и дней недели, команды меню;
- `master.ts` — уведомления Динаре и текст событий в Google Calendar;
- `services.ts` — услуги и их длительность;
- `location.ts` — адрес и «как добраться».

## Логика

**Запись**: услуга → месяц → день (сетка календаря) → время → имя → телефон → комментарий/фото-референс (можно пропустить) → подтверждение.
- Услуги, цены и длительность — `src/data/services.ts` (макияж 60 мин, причёска 60 мин, полный образ 120 мин).
- Недоступные дни в календаре зачёркнуты и при нажатии объясняют причину.
- Слоты по часу; записаться можно не позже чем за 2 часа; запись открыта на `BOOKING_DAYS_AHEAD` дней.

**Занятость** = активные записи в БД + события в Google Calendar Динары со статусом «Занят».
Чтобы закрыть время или день (личные дела, отпуск) — создайте в календаре событие, для события на весь день выберите статус **«Занят»** (по умолчанию у таких событий «Свободен»). События, созданные ботом, не учитываются повторно.

**Защита от двойной записи**: в PostgreSQL на таблице `bookings` стоит exclusion-constraint — активные записи не могут пересекаться по времени. Два клиента не займут одно время даже при одновременном нажатии и при нескольких инстансах бота.
Кнопки со временем проверяются на сервере (рабочие часы, запас 2 ч, окно записи, занятость) — старое сообщение не позволит записаться на прошедшее или занятое время.

**Сессии** (шаги записи) хранятся в PostgreSQL — рестарт или деплой не обрывает начатую запись.

**Мои записи** (`/my`): список записей кнопками → карточка записи → «Перенести» / «Отменить» (отмена с подтверждением). Перенос и отмена — не позднее чем за `MODIFY_DEADLINE_HOURS` (2 ч) до начала. При переносе событие в календаре сдвигается, при отмене — удаляется; мастер получает уведомление.

**Напоминания клиенту**: за 24 ч (с кнопками «Подтверждаю» / «Перенести» / «Отменить» / «Как добраться») и за 2 ч. Подтверждение клиента приходит мастеру.

**Панель мастера** (`/start` или `/master` из чата `MASTER_CHAT_ID`):
- «Сегодня» / «Завтра» с листанием по дням и «Все предстоящие» (постранично); ✅ — клиент подтвердил запись.
- Карточка записи: данные клиента, фото-референсы, **перенос** (тот же календарь свободных слотов) и **отмена** (с подтверждением). Ограничение «за 2 часа» на мастера не действует. Клиент получает уведомление об отмене/переносе, календарь Google обновляется.
- В уведомлениях о новой записи, переносе и подтверждении — кнопка «📋 Открыть запись».
- **Напоминание мастеру за 2 часа** до записи (если запись сделана менее чем за 2,5 ч — не дублируется, уведомление о новой записи уже пришло).
- «⭐ Отзывы» (`/reviews`) — все отзывы, новые сверху (📢 — опубликован); в карточке отзыва — «Опубликовать» / «Скрыть».
- Меню команд у мастера — только «Записи» (`/master`) и «Отзывы» (`/reviews`). «Записаться», «Мои записи», «Как добраться» — только для клиентов: у мастера эти команды открывают панель.

**Отзывы**: на следующий день после записи в `REVIEW_HOUR` бот просит оценку 1–5 и пару слов. Отзыв приходит Динаре с кнопкой «Опубликовать» — опубликованные видны клиентам в боте («⭐ Отзывы») и на сайте.
